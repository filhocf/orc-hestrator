# orc-presence — being visible and not colliding

Orc is a central, cross-machine board. When more than one agent uses it — the
same persona running on three machines, or different personas on the same
backlog — presence stops two agents from silently grabbing the same item and
makes authorship real. This skill is only needed in that multi-agent case; a
solo agent on a private board can skip it (but still benefits from authorship).

## CRITICAL — the identity triple

Identity is the triple **(hostname, agent_id, session_id)**:

- **agent_id** comes from the `X-Agent-ID` header (ADR-005). It is **not** a tool
  argument — you cannot pass it to `agent_register`. If the client does not send
  the header, writes land with `created_by: null` and `agent_list` shows you as
  `(anon)`. That is the signal your identity is not wired.
- **hostname** comes from the `hostname` argument → `X-Client-Hostname` header →
  `"unknown"`.
- **session_id** is **generated by `agent_register` and returned to you. Reuse
  it** for the whole session — every `claim`, `conflicts`, `heartbeat`, and
  `agent_end` call needs the same `session_id`. Do not register twice per session.

Two sessions with different `session_id` are two agents even if the persona and
host are identical — a claim held by one conflicts with the other.

## Session lifecycle

```
# at start — register once, keep the returned session_id
r = agent_register(hostname="DNBSCDC289", cli="kiro")
session_id = r.session_id

# every 2–3 minutes while working
agent_heartbeat(session_id=session_id)

# on exit — release presence so stale sessions do not linger
agent_end(session_id=session_id)   # CASCADE: also releases every claim this session held
```

`agent_register` also accepts `pid` and `theme` (optional, for the human-readable
label). Heartbeat keeps the session from being reaped; a session that stops
heartbeating is lazily reaped by the server, so a crashed agent does not hold
claims forever.

See who else is on the board:

```
agent_list()                       # all active sessions, every machine
agent_list(hostname="sirdata")     # filter by any level of the triple
agent_list(agent_id="zero")
```

Each row shows the triple plus a readable label — use it to answer "is another
agent already working here?" before you start.

## Claims — grab before you touch

A claim marks a subject as yours so another session knows to stay off it. A
subject is either a **work item** or a free-form **resource** (a file, a branch).

```
# claim a work item before advancing it
claim(subject_type="work_item", subject_ref="<item-id>", session_id=session_id)

# claim a resource you are about to edit (file, branch)
claim(subject_type="resource", subject_ref="src/engine/items.py",
      resource_type="file", session_id=session_id, expires_at="<optional ISO>")

# release when done (or let it expire)
release(...)   # same subject, same session_id
```

`claim` returns `CONFLICT` naming the holder's triple if another session already
holds that subject — even if it is the same persona on the same host but a
different `session_id`. Treat the conflict as a stop sign: coordinate or pick
another item, do not force it.

`expires_at` (optional ISO 8601) lets a claim auto-expire so a forgotten claim
does not block the team indefinitely. Prefer an explicit `release` on exit.

## Check before a batch

Before starting a set of items or editing a set of files, ask which are already
taken:

```
conflicts(subjects_json=[["work_item","id1"], ["resource","src/db.py"]],
          session_id=session_id)
```

It returns, for each subject, the holder's triple if another (non-expired)
session owns it. Empty result = clear to proceed.

## Reflex summary

- Register once at start, **keep the session_id**, heartbeat every 2–3 min, end
  on exit.
- `created_by: null` or `(anon)` in `agent_list` → your `X-Agent-ID` is not set;
  fix the client header before relying on authorship.
- Claim a work item before `advance_item(trigger="start")` on a shared board;
  claim a file/branch before editing it.
- A `CONFLICT` names who holds it — coordinate, do not override.
- Release (or expire) claims so you do not strand the team.
